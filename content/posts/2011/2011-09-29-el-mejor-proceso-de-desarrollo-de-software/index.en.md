Forget agile and the manifestos, the best process for developing
software is very simple.

1.  Understand the problem. At this point it's good to talk to the
    user, and listen.
2.  Write down somewhere what needs to be done.
3.  Sit down and code the solution.
4.  Ship to production.
5.  Fix the bugs quickly and go back to step 4.
6.  If it works, find another problem to solve.

This process gets better if you don't ask the users for too many opinions and
you have programmers who can actually program. :wink:
